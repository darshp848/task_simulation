## The constraint that decides what fits

The harness can only send prompt / start / stop / home / reset and read the debug-view trips (~3.4 s cadence).
It can't see or change Dream-1's actions. So methods that re-rank sampled actions (RoboMonkey), steer with a
world model (FOREWARN) or filter actions (CBF safety filters) don't apply unless Dream exposes action chunks.
Worth asking the Dream Labs people on site; until then, skip them.

## 1. Make the start state match the training data (LIBERO-Plus)

LIBERO-Plus (OpenVLA-OFT, 97.1% baseline): robot initial state -59.9 pts, camera viewpoint -37.4, layout -20.0,
language only -15.6. Models often ignore the instruction: removing it barely changed results; swapping the target
object still made them grab the original one.

For us:
- The prompt is a weak lever. The sim prompt results (named arm 0/8 vs 2/4; drop-cable 2/5 vs 0/3) are within noise.
- The start pose and the cameras are strong levers. Compare the joint state at each `/start` against the first frame
  of the NUC teleop episodes (`nuc_data`). If they differ, `/home` before the stage starts, not only on `home_and_retry`.
- Save a reference overhead frame at match start; flag a camera that moved (frame diff on fixed table features).

## 2. Close the guard race with live frames (Code-as-Monitor)

Code-as-Monitor (CVPR 2025): a VLM writes a geometric check once per subgoal; the check then runs on tracked
elements every frame with no further VLM calls. Proactive checks halt before the failure (pan tilting before the
food falls). 31.8% less execution time, 28.7% higher success under heavy disturbance.

For us: the illegal-ball loss is a latency problem (frames a trip old, pick-to-bin in seconds; 2/6 sim matches
still lost with `detect.py`). Feed the LiveKit video (on `codex/hill-climb-livekit`, not on main; also +10 on the
rubric) into `detect.py` and run the guard at video rate. Proactive rule: white ball inside the gripper box →
`/stop` before the lift.

## 3. Geometric stage checks first, Haiku as tie-breaker (Code-as-Monitor)

Short `confirm: 1` stages (balls, put-downs, arms_clear) wait ~4 s per monitor call. The detector can count balls
in the bin, blocks in the tower and cables out of the hub each poll. Use those as the primary signal and call
Haiku only when they disagree or confidence is low.

## 4. Calibrate the monitor on real frames (FAIL-Detect, FIPER, SAFE)

These three set alarm thresholds with conformal prediction on successful runs, which bounds the false-alarm rate.
They use the policy's own features, which we don't have, but the same calibration works on the monitor's
`progress`/`confidence` and on the detector's counts. Data: the NUC split episodes have labelled stage boundaries
(unplug → put down). Measure early/late "done" calls and pick `confirm` and confidence thresholds from them.
Needs an Anthropic API key on the cluster.

## 5. Evaluate with enough trials (STEP, SIMPLER)

STEP (RSS 2025): gaps of 30-50 points resolved in ~7-35 trials; a 9-point gap needs ~500. Typical robotics evals
run 10-60. Our prompt A/B runs were 3-8 matches each. Add a sequential stopping rule to `cluster/run_matches.sh`
so a batch stops once the answer is clear and keeps running when it isn't.
SIMPLER (CoRL 2024): sim ranks track real ranks only when the sim matches what the cameras see ("visual matching").
Our sim layout is guessed and runs base Dream-1 in joint mode. Before trusting sim-only decisions, check that
per-stage rates in sim and on the station rank the same way for at least one change.

## 6. Training-phase data from the harness (RaC, IntervenGen)

RaC: fine-tune on human interventions where each recovery segment (back to a safe state) is followed by a
correction segment, and the episode ends when the intervention ends. Results scale with recovery count.
The harness already writes `segments.jsonl`. When it calls a stall, hand control to teleop and record
recovery + correction as one episode with the stage's task text (keeps the byte-for-byte rule).

## 7. Failure-reasoning models (AHA)

AHA (ICLR 2025) fine-tunes a VLM on failures generated by perturbing sim demos. Our sim referee can generate
labelled failures (dropped cable, fallen tower, binned illegal ball) to test Haiku before a match. Training our
own model isn't worth it this weekend.

## Order

1 and 2 are cheap and attack the two biggest losses (start-state sensitivity, guard latency). 4 needs the API key.
5 changes how every later decision is made. 6 is for the training phase.
